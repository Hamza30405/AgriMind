# 🌾 AgriMind

> نظام ري ذكي بيراقب رطوبة التربة والحرارة والرطوبة بحساسات على ESP32، ويتحكم في طلمبة المياه يدويًا أو تلقائيًا، ويعرض كل ده في تطبيق Flutter مع تنبيهات وتحليلات.

---

## 📖 فكرة المشروع

الري بالتخمين بيسبب هدر في المياه، أو نبات عطشان من غير ما حد ياخد باله. **AgriMind** بيقيس حالة التربة والجو بشكل مستمر، ويقرر (أو يسيبك تقرر) إمتى الطلمبة تشتغل، ومعاها حماية تمنع تشغيل الطلمبة بشكل غلط أو لفترة طويلة.

---

## ✨ المميزات

| الميزة | الوصف |
|--------|-------|
| 📡 مراقبة لحظية | رطوبة التربة، درجة الحرارة، ورطوبة الجو بتتحدث كل بضع ثواني |
| 💧 ري يدوي | تشغيل وإيقاف الطلمبة من التطبيق |

| 🛡️ حماية الطلمبة | إيقاف تلقائي لو الجهاز فصل، حد أقصى لمدة التشغيل، وفترة راحة بعد كل دورة |
| 🔔 تنبيهات | رطوبة منخفضة، حرارة عالية، الجهاز offline/online، تخطي أقصى مدة، وعدم تطابق حالة الطلمبة |
| 📊 تحليلات | رسوم بيانية لآخر 24 ساعة ومتوسط آخر 7 أيام، وسجل تشغيل الطلمبة |

## 🏗️ معمارية النظام

```
 ┌────────────────────┐   WiFi    ┌──────────────────────┐          ┌──────────────┐
 │       ESP32        │ ────────► │       Backend        │ ◄─────── │ تطبيق Flutter │
 │ حساسات + ريلاي+LCD │ ◄──────── │ Express + SQLite     │          └──────────────┘
 └────────────────────┘ أمر الطلمبة└──────────────────────┘
      (DEVICE_KEY)                                                    (APP_KEY)
```

- الـ **ESP32** بيبعت القراءات للسيرفر، والسيرفر بيرد عليه بحالة الطلمبة المطلوبة.
- التطبيق بيكلم السيرفر بس، **مش بيتصل بالجهاز مباشرة**.
- كل طرف له مفتاح منفصل (`DEVICE_KEY` للجهاز و`APP_KEY` للتطبيق).

### الهاردوير

| القطعة | الوظيفة | الـ pin الافتراضي |
|--------|---------|-------------------|
| ESP32 | المتحكم الرئيسي ومنصة الواي فاي | — |
| حساس DHT (DHT22 أو DHT11) | درجة الحرارة والرطوبة | GPIO4 |
| حساس رطوبة التربة (capacitive) | رطوبة التربة | GPIO34 |
| موديول ريلاي | تشغيل وإيقاف الطلمبة | GPIO26 (active-LOW) |
| طلمبة مياه DC | الري | عبر الريلاي ومصدر كهربا منفصل |
| شاشة LCD I2C 16x2 | عرض الحالة | SDA 21 / SCL 22 (عنوان 0x27) |

> ⚠️ الطلمبة **ماتتغذاش من الـ ESP32 أبدًا**. الريلاي بيفصل ويوصّل الطرف الموجب لمصدر كهربا الطلمبة (COM وNO).
> لو الطلمبة بتشتغل على كهربا الحيط (220V) خلّي حد عنده خبرة يوصّل الجزء ده.

## 🛠️ التقنيات المستخدمة

- **Backend:** Node.js 22+، Express 5، SQLite (`better-sqlite3`)
- **التطبيق:** Flutter (Dart)، حزم `http` و`shared_preferences`
- **الجهاز:** ESP32 (Arduino)، مكتبات ArduinoJson وDHT sensor وLiquidCrystal I2C
- **أدوات:** Git، `node --test` للاختبارات

## 🚀 طريقة التشغيل

### 1) الـ Backend

محتاج **Node.js 22 أو أحدث**.

```bash
cd backend
npm install
cp .env.example .env
npm start
```

اعمل مفتاحين مختلفين وقويين وحطهم في `.env`:

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

```env
DEVICE_KEY=مفتاح-الجهاز
APP_KEY=مفتاح-التطبيق
```

| المتغير | الوظيفة |
|---------|---------|
| `PORT` / `HOST` | بورت وعنوان السيرفر (3000 افتراضيًا) |
| `DEVICE_KEY` / `APP_KEY` | مفاتيح الجهاز والتطبيق. في production لازم 16 حرف على الأقل ومختلفين |
| `DB_PATH` | مكان قاعدة البيانات (`./data/agrimind.db`) |
| `RETENTION_DAYS` | مدة الاحتفاظ بالقراءات (30 يوم) |
| `OFFLINE_AFTER_SECONDS` | بعد كام ثانية من الصمت الجهاز يتحسب offline (30) |
| `CORS_ORIGINS` | الأصول المسموح بها (لو التطبيق ويب) |
| `TRUST_PROXY` | `1` لو السيرفر ورا reverse proxy |

للنشر على الإنترنت حط السيرفر ورا **HTTPS** (Caddy أو nginx أو منصة استضافة)، أو استخدم `TLS_KEY_FILE` و`TLS_CERT_FILE`.

### 2) الـ ESP32

1. ثبّت من Arduino Library Manager: **ArduinoJson (v7)**، **DHT sensor library**، **LiquidCrystal I2C**.
2. عدّل `firmware/agrimind_esp32/config.h`:
   - `WIFI_SSID` و`WIFI_PASSWORD` (شبكة 2.4GHz)
   - `SERVER_URL` بعنوان الجهاز اللي عليه السيرفر، مثلًا `http://192.168.1.5:3000`
   - `DEVICE_KEY` نفس القيمة في `.env`
   - الـ pins، ونوع الـ DHT (`DHT22` أو `DHT11`)
3. **معايرة حساس التربة:** اقرا القيمة الخام في الهوا وحطها في `SOIL_RAW_DRY`، وفي كوباية مية وحطها في `SOIL_RAW_WET`.
4. اختار Board **ESP32 Dev Module** وارفع الكود.

### 3) تطبيق Flutter

```bash
cd flutter_app
flutter pub get
flutter run
```

أول مرة التطبيق هيطلب **عنوان السيرفر** و**APP_KEY**، وبيتحفظوا على الجهاز.

- Android emulator: استخدم `http://10.0.2.2:3000`.
- على أندرويد لازم صلاحية `INTERNET` في `AndroidManifest.xml`، ولو بتستخدم `http://` على الشبكة المحلية ضيف `android:usesCleartextTraffic="true"`.

## 🛡️ قواعد أمان الطلمبة

| القاعدة | التفاصيل |
|---------|----------|
| بعد تشغيل السيرفر | الطلمبة دايمًا OFF |
| الجهاز offline | الطلمبة بتتقفل ومبترجعش تشتغل لوحدها |
| أقصى مدة تشغيل | `maxPumpMinutes` (10 دقايق افتراضيًا)، وبعدها فترة راحة |
| بعد دورة تلقائية | فترة راحة `cooldownMinutes` |
| التشغيل اليدوي | مرفوض لو الجهاز offline أو في راحة أو الوضع تلقائي |
| تأكيد من الجهاز | الجهاز بيبعت حالة الريلاي الفعلية، ولو مختلفة عن المطلوبة بيتطلع تنبيه |
| حماية داخل الـ ESP32 | بيقفل الطلمبة لوحده لو السيرفر مردش 25 ثانية أو عدّت أقصى مدة |

## 🔌 الـ API

كل المسارات بتحتاج هيدر `x-api-key`.

| الطريقة | المسار | المفتاح | الوظيفة |
|---------|--------|---------|---------|
| POST | `/api/readings` | الجهاز | الجهاز يبعت القراءات ويستلم حالة الطلمبة المطلوبة |
| GET | `/api/status` | التطبيق | الحالة الحالية |
| POST | `/api/pump` | التطبيق | تشغيل/إيقاف يدوي `{ "enabled": true }` |
| GET / PUT | `/api/settings` | التطبيق | الوضع (manual/auto) والحدود |
| GET | `/api/history?limit=&hours=` | التطبيق | القراءات |
| GET | `/api/history/daily?days=` | التطبيق | متوسط وأقل وأعلى قيمة لكل يوم |
| GET | `/api/pump/events` | التطبيق | سجل تشغيل الطلمبة |
| GET | `/api/alerts` | التطبيق | التنبيهات |
| POST | `/api/alerts/ack` | التطبيق | تحديد التنبيهات كمقروءة |
| GET | `/health` | — | فحص سريع |

مثال:

```bash
curl -X POST http://localhost:3000/api/pump \
  -H "x-api-key: APP_KEY" \
  -H "Content-Type: application/json" \
  -d '{"enabled": true}'
```
